# Промпт для продолжения: мультиплеер «Железного Стяга»

Скопируй всё ниже в другую нейросеть (с доступом к репозиторию и shell).

---

Ты продолжаешь работу над браузерной игрой «Железный Стяг» (инди-Bannerlord в стиле Battle Brothers; бой армий в реальном времени + карта мира). Репозиторий `akglebak16/iron-standard`, ветка `main`. Код — несколько JS-файлов в `src/`, `node build.mjs` склеивает их в один `index.html` (одиночная игра, раздаётся через GitHub Pages — **её нельзя сломать**). Язык интерфейса и общения с владельцем — русский. npm/pip install недоступны в моей среде; у тебя, возможно, есть — но сервер должен остаться **без зависимостей** (чистый Node.js, свой WebSocket RFC6455 поверх `http` upgrade).

## Цель
Реалтайм-мультиплеер на 2 игрока (владелец + друг, только десктоп-браузер) на Railway ($5 план): общая кампания на сервере, одна ссылка. Одиночный режим остаётся.

## Согласованные правила
- Мир общий, серверный, часы идут всегда на ×1 (сутки ≈ 60–90 с реального времени); пауза/×2/×4 — только по согласию обоих (голосование).
- Поселения безопасны. Жалованье/еда игрока не списываются, пока он в бою. Мир идёт, пока идёт бой.
- У каждого игрока свой герой/армия/золото/снаряжение; доски заданий и мир общие; золото/еда/войска можно передавать, когда рядом (снаряжение — позже, нужен инвентарь).
- Фракции игроков: можно создать общую (общее знамя/имя/репутация, союзники, без friendly fire, чат) или остаться отдельными. PvP нет.
- Бои считает сервер, несколько боёв одновременно. К бою друга можно присоединиться, только если очень близко на карте и только на его стороне; можно начать свой бой или продолжать заниматься делами.
- Дисконнект в бою — ИИ берёт героя и армию. Оффлайн-игроки на карте скрыты.
- Сохранение мира на сервере (этап 2), вход по имени + общий код.

## Этапы
1. Сервер + общий мир + отдельные бои против ИИ (**текущий**).
2. Сохранение на сервере + логин.
3. Фракции + передачи (золото/еда/войска).
4. Присоединение к бою друга / кооп-герой (в симуляции пока один `B.hero`).
5. Инвентарь + передача снаряжения.

## Состояние кода (что уже сделано)
- `src/01_core.js` — утилиты, данные. Есть `const SERVER = typeof __SRV !== 'undefined';` — сервер загружает симуляцию, определив `__SRV`.
- `src/03_battle.js` — боевая симуляция подготовлена для сервера: `ev([...])` копит события в `B.ev` (h=урон, k=смерть, a=стрела, b=искры, d=пыль, t=текст, l=лог); ввод героя через `h.inp = {dx,dy,face,atk,blk,spr}` (`NOINP` по умолчанию); `giveOrder(ord,wx,wy,selArg)`; `h.ai`/`h.pid` из `cfg.heroAI`/`cfg.heroPid`; отрисовка/спрайты/трупы под `!SERVER`; `battleCamera` вынесена из `battleUpdate`.
- `src/05_world.js` — симуляция мира, **многопользовательская**: `G.players[]` (игрок: `id,x,y,troops,gold,food,path,pi,tid,sid,in(id поселения),name,culture,banner,busy,away,log,quests,rel,stats,hero`), `newWorld/addPlayer/newGame`, `stepWorld(dh)` возвращает массив событий `{type:'enter'|'meet',P,s|p,forced}`, `hourTick/dayTick/playerDay` (пропускают `away` и `busy==='battle'`), `logW(txt,kind,P)`, `acceptQuest(P,q)`, `questDone(P,q,why)`. В одиночке `G.player = G.players[0]`.
- `src/05b_worldart.js` — только клиент (рисование ландшафта/поселений).
- `src/05c_logic.js` — общая логика для клиента и сервера: `xpNeed, heroBattle, townEnter, doHire/doGear/doFood/doUpgrade/doAttr/doAccept, relativePowerOf, encAttack, encFlee, battleCfgFor(P,p), autoResult(P,p), applyBattleResult(P,res,p)`.
- `src/06_ui.js`, `src/07_main.js` — одиночный UI/цикл, уже переведены на эти API (`readHeroInput()` заполняет `B.hero.inp`). Проверено Playwright'ом: новая игра, симуляция мира 200 дней, город, расчётный бой, сохранение/загрузка (ключ `zhelezny-styag-save-2`), запуск боя с вводом героя.
- `src/02_art.js` — клиентская процедурная графика; `getHeroSprite` нужно расширить параметром фракции/знамени для героя другого игрока.

## Известный хвост одиночки
Мелкая проверка: при ручном убийстве всех врагов в тесте (`u.hp=0` для side 1) модалка итогов не появилась за 5 с — проверь, что завершение боя (`B.over` → `cfg.onEnd`) работает штатно в обычной игре (вероятно, дело в способе убийства в тесте, но удостоверься).

## Что сделать на этапе 1
1. `package.json` (`"start": "node server/index.js"`, без зависимостей), `server/ws.js` (минимальный RFC6455: handshake, текстовые кадры, ping/pong, маскирование клиентских кадров), `server/index.js`:
   - раздаёт собранный `index.html` (или отдельную мультиплеерную сборку) по HTTP на `process.env.PORT`;
   - загружает sim-файлы (`01_core, 03_battle, 05_world, 05c_logic` + серверные стабы `sfx`, `FACTIONS.player` цвета и т.п.) через обёртку-функцию с флагом `__SRV` (в `03_battle` глобал `B` подменяется на бой через `setB/getB` — реализуй, если ещё нет);
   - мир тикает всегда (×1), `stepWorld` по таймеру; игроки: join по имени, ограничение 2; снапшоты мира ~5 Гц (позиции партий/игроков, сутки/час, личные: золото, еда, войска, лог, квесты, rel);
   - действия клиентов: клик-движение, вход/выход из поселения, найм/снаряжение/еда/квесты/улучшения/очки (через `do*` из `05c_logic`), встреча (бой / расчёт / бегство / разойтись), голосование паузы/скорости;
   - бои: каждый — свой `B` на сервере, снапшоты ~15 Гц + `B.ev`, ввод героя и приказы от клиента; блокировка столкнувшейся партии (`p.lock`) и таймаут; по концу — `applyBattleResult`; дисконнект → `h.ai=true`.
2. `src/08_net.js` + изменения `06_ui/07_main`: пункт «Играть вдвоём» в меню, диалог (имя, код, культура, знамя), режим-зеркало мира и боя (клиент только рисует снапшоты с экспоненциальным сглаживанием и шлёт ввод), показ второго игрока на карте, UI голосования за паузу/скорость, чат.
3. Тест локально двумя браузерами (Playwright), README + инструкция деплоя на Railway (проект из репозитория, старт `npm start`, публичный домен).
4. Коммитить в `main`, одиночную сборку `index.html` не ломать (проверь `node build.mjs` и открой в Playwright).

## Правила работы
- Объясняй владельцу по-русски, коротко, без жаргона. Не задавай лишних вопросов — решения по правилам выше уже согласованы.
- Код — серверно-авторитетный: клиент не доверяется.
- После каждого этапа — тест и коммит.
