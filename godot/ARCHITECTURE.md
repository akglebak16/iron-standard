# Архитектура Godot-версии

Этот документ обязателен для Claude, Codex и других помощников при работе в `godot/`. Браузерный прототип в `src/` служит эталоном поведения до полного переноса. Новую механику размещаем в Godot-проекте по игровому модулю.

## Дерево проекта

```text
godot/
  project.godot
  app/               # точка входа, сборка модулей, главное меню
  tools/             # запуск проверок всего Godot-проекта
  battle/            # всё, что принадлежит бою
    config.gd        # общие правила и параметры боя
    model/           # состояние боя и сущности: state, unit, group
    rules/           # расчёты и действия: damage, combat, hero_control
    data/            # каталог и определения войск
    presentation/    # сцена, рисунок, настройки одной встречи
    tests/           # model/, rules/, data/, presentation/
    tools/           # сверка и разовый перенос данных боя
```

Ищи функциональность сначала по игровому модулю, затем по роли файла: `battle/rules/` для формулы удара, `battle/data/` для характеристик войск, `battle/presentation/` для рисунка. Тест размещай в `battle/tests/` в подпапке той области, которую он проверяет. Тест, проверяющий несколько областей, клади по основной проверяемой способности. Так же организуй будущий `campaign/` и другие игровые модули, когда появится их код.

Не создавай пустые подпапки заранее. Если в модуле один общий файл, например `battle/config.gd`, оставь его в корне модуля. Когда появляется несколько файлов одной роли, создай подпапку с названием роли. Общий для нескольких модулей код выноси в `shared/` только после второго реального использования; инструменты всего проекта размещай в корневом `tools/`.

## Границы кода

- `app/` запускает игру и связывает модули. Боевые формулы и значения там не живут.
- `battle/model/state.gd` и связанные классы работают с данными без сцены и окна. `rules/` меняет модель по игровым правилам. `presentation/` читает состояние и передаёт команды; отрисовка не определяет урон и движение.
- Настраиваемые числа и коды приказов именуются в `battle/config.gd`. Состав войск и их характеристики редактируются в `battle/data/troops.json`. Не дублируй одну настройку в нескольких местах.
- Настройки одного демонстрационного боя и его временного рисунка лежат в `battle/presentation/demo_config.gd`, отдельно от общих боевых правил.
- Идентификаторы войск стабильны (`n1`, `e3c` и т. п.); текст для игрока при переносе интерфейса перейдёт в локализацию RU/EN. Сохранения новой версии получат отдельную версионированную схему.
- Сетевой режим отложен и остаётся зоной Глеба. Не связывай одиночную симуляцию с `server/` или сетевыми файлами браузерной версии.

## Проверка и коммиты

Запускай тесты изменённого модуля из его `tests/`; перед коммитом запускай весь набор через `node godot/tools/test.cjs <путь-к-godot.exe>`. Скрипт проверяет ошибки компиляции и зависание, потому что Godot иногда возвращает код 0 при ошибке в зависимом GDScript. Сверка исходных данных: `node godot/battle/tools/export_troops.cjs --check` до намеренной правки баланса. Браузерные тесты при переносе Godot не запускаем по решению владельца; они проверяются в GitHub. Каждый успешный этап завершается коротким русским коммитом вместе с `CHANGELOG.md` и полезным уроком в `shareness/lessons.md`.
