# Окружение измерения

2026-11-15 один и тот же Windows release exe, contact 1000×1000, seed 4242,
60 warmup + 180 measured ticks, profile-phases:

| Запуск | simulation p95, мс | snapshot p95, мс |
|---|---:|---:|
| sandbox, 1 | 71.440 | 11.985 |
| sandbox, 2 | 79.601 | 13.358 |
| sandbox, 3 | 75.372 | 12.029 |
| host, 1 | 35.454 | 5.203 |
| host, 2 | 31.737 | 4.561 |

Состав и счётчики событий совпали. Механизм накладных расходов sandbox не
установлен; смешивать эти распределения в регрессионном сравнении нельзя.
Performance-приёмка запускается на хосте; sandbox пригоден для функциональных
проверок. Ни частота CPU, ни схема питания при сравнении не менялись помощником.
Это короткая диагностика, не приёмка FPS и не утверждённый baseline.

`release.cjs` теперь пишет `<exe>.build.json`: SHA ревизии и содержимого исходников
(включая новые файлы), SHA самого exe со встроенным PCK, дату, успешный smoke.
`benchmark.cjs` проверяет этот файл и по умолчанию отвергает устаревшую сборку.
Для намеренного сравнения старого артефакта есть `--allow-stale-build`; отчёт
сохраняет идентичность именно сборки, а не текущего checkout.
Запуск обязательно помечается `--execution-context=host` или `sandbox`.
`unspecified` сохранён для совместимости, такой отчёт не годится для приёмки.

Характеристики эталона зафиксированы в `reference-windows.json`. Проверка
привязки артефакта: `node godot/tools/build_identity.test.cjs`.
