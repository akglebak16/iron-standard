# Карта кампании: повторная отрисовка неподвижного декора

2026-11-15, Windows, i5-14400F, RTX 4070 SUPER / драйвер 610.60,
Godot 4.7.2, Compatibility, 1920×1080, VSync off, max_fps=0, seed 4242.
Оптимизация представления не меняет правила мира, RNG и состав отрядов.

## Диагноз

Исходное поведение ревизии 05f7543 с добавленным диагностическим скриптом:
[профиль по слоям](campaign-layer-profile.json). Фазы выполнялись последовательно
в одном процессе: 60 кадров прогрева и 120 измеряемых кадров на фазу.
Все фазы, кроме baseline, ставили мировое время на паузу; отключение слоёв
использовалось только для локализации затрат.

| Фаза | Средний кадр, мс | p95, мс | Draw calls, среднее |
| --- | ---: | ---: | ---: |
| Вся карта, время идёт | 80,31 | 87,65 | 28 600 |
| Вся карта, пауза | 75,34 | 78,02 | 28 610 |
| Скрыт рисунок карты, HUD остаётся | 0,56 | 0,78 | 31 |
| Скрыт рельеф/растения/блики воды | 39,95 | 42,18 | 11 781 |

Основа земли уже запекалась. Остальные неподвижные слои сохраняли команды
CanvasItem, которые renderer вновь обрабатывал каждый кадр. CPU-render baseline
~64 мс, GPU-render ~57,5 мс; эти интервалы нельзя складывать из-за перекрытия.
Тайминги снимаются через [RenderingServer](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-viewport-set-measure-render-time).

## Изменение

`static_map_cache.gd` запекает землю, фермы, рельеф, дороги, реки, мосты и виньетку
после завершения исходных GPU-проходов. Два texel на единицу мира дают текстуру
10400×6800. После отрисовки UPDATE_DISABLED запрещает повторную работу, а исходные
команды и промежуточные viewport освобождаются. Кэш принадлежит контексту карты
и удаляется вместе с ним. Поселения, владельцы/подписи, отряды, осады и HUD
остаются отдельными живыми слоями.

Перед подготовкой рисунка отрядов видимая область переводится в мировые
координаты и расширяется на 64 единицы для знамени, кольца и тени. Отряды за
пределами этой области не создают графические команды; их симуляция продолжается.
Порядок перекрытия видимых отрядов сохраняется.

## Проверка изображения и ограничений

Оконный `test_campaign_render_cache.gd` сравнивает прежний и новый рисунок одного
мира на масштабах 0,25 / 0,9 / 2,5. [Результаты](campaign-cache-visual.json):
средняя абсолютная разница каналов 0,154% / 0,250% / 0,252%. Проверены исходные
слои, отдельное положение динамических поселений, отключение повторной отрисовки
и освобождение исходной геометрии. Небольшая разница — фильтрация запечённого
рисунка; это не побитовая идентичность изображений.

Кэш обменивает время кадра на видеопамять. На этом ПК её общий расход в коротком
прогоне составил ~629 МиБ. Это решение проверено на эталонной видеокарте;
бюджет/размер текстуры для слабых устройств ещё требует отдельной проверки.

## Release: минутные прогоны

[Полный отчёт с SHA exe/DLL/исходников](campaign-cache-release.json), ревизия
`9bcc1a5ec942dc18760c6ee59a5a38590d62e753`. Все четыре запуска последовательные,
по 60 секунд измерения после прогрева, отдельные профили пользователя, обычный
Windows scheduler. Игровая скорость ×1, время не было на паузе; каждый запуск
дошёл до дня 4. Запуски с разной частотой кадров не являются побитовым replay
кампании: в конце 104–105 отрядов, число записано в отчёте.

| Режим | mean, мс | p50, мс | p95, мс | p99, мс | draw calls, среднее |
| --- | ---: | ---: | ---: | ---: | ---: |
| Без кэша, отсечение отрядов включено | 74,18 | 72,51 | 84,22 | 97,49 | 27 631 |
| Кэш, повтор 1 | 11,02 | 10,04 | 17,77 | 21,01 | 1 801 |
| Кэш, повтор 2 | 11,16 | 10,20 | 17,90 | 21,75 | 1 800 |
| Кэш, движение камеры и три масштаба | 10,88 | 8,48 | 19,86 | 27,95 | 1 724 |

В неподвижной камере средний CPU-render снизился с 62,64 до 4,73–4,75 мс,
GPU-render — с 56,74 до 2,48–2,53 мс. Среднее время полного кадра улучшилось
примерно в 6,7 раза. p95 ещё превышает 16,67 мс; постоянные 60 FPS этим отчётом
не подтверждаются. Это диагностика карты, не полная приёмка blueprint.

Видеопамять: ~191,6 МиБ без кэша, ~613 МиБ с неподвижной камерой и ~629 МиБ
в маршруте камеры. Цена кэша в неподвижной камере — около 421 МиБ.
В двух минутных прогонах с кэшем разница первой/последней выборки — около
0,55 МиБ; такой интервал недостаточен для утверждения об отсутствии всех утечек.

## Воспроизведение

Полная игра и диагностический запуск используют один и тот же кэш по умолчанию.
Для release после engine-аргументов передаются:

```text
-- --view-benchmark --mode=campaign --seed=4242 --measure-seconds=60 --out=<absolute-report.json>
```

Для сравнения прежнего статического рисунка добавить `--map-cache=off`.
Отсечение невидимых отрядов при этом остаётся: этот режим изолирует эффект кэша,
а не воспроизводит всю старую ревизию. `--camera-route` проводит камеру по карте
с последовательными масштабами 0,25 / 0,9 / 2,5 каждые десять секунд.
Перед `--`: `--resolution 1920x1080 --disable-vsync --max-fps 0`.

Тесты запускаются с отдельными APPDATA/XDG_DATA_HOME. Отчёт фиксирует elapsed,
процентили кадров, CPU/GPU-render, draw calls, активный кэш, часы мира и память.
Результаты карты не заменяют приёмку настоящего боя 1000×1000.

Проверки: architecture gate и отрицательные fixtures; пять выбранных Godot-файлов
(кэш, камеры, lifecycle, UI, terrain parity); отдельная оконная сверка изображений;
оконные mode lifecycle и Campaign → Battle → Campaign; экспортированный
release-smoke. Полный набор Godot-тестов для этой правки повторно не запускался.
