# Перенос графики и интерфейса

Эталон: `src/` на коммите `096df30ad9e279d89aacff7dc4e8720903e8a700`. Это проверяемый этап переноса, **не полный попиксельный паритет**.

## Перенесено

- 536 вариантов войск (67 типов × две палитры × четыре исходных варианта): тело, оружие, портрет, голова, обезглавленный силуэт, белая вспышка и два слоя павшего бойца без подставки.
- 872 исходных слоя для сборки штатных шлемов, доспехов, щитов, оружия и коней героя; одни изображения используются в бою, обозе и на карте.
- 10 гербов, 62 SVG-иконки в трёх палитрах, 280 сочетаний поселения, культуры и владельца, караван. Альфа-цвета SVG преобразованы в совместимые с Godot атрибуты: мелкие штрихи больше не пропадают.
- Исходные растения четырёх биомов и исходная земля поля 2600×1700.
- Шрифты Alegreya SC Bold, Alegreya Sans Medium и Bold с полными SIL OFL лицензиями, работающие офлайн.
- Тема из окончательного CSS: деревянная фактура, заклёпки, фаски, кнопки и цвета.
- Заглавный экран с фоновым боем, создание героя, справка, переходы к полевому бою и осаде.
- Размещение HUD карты, пергаментный журнал, оформление окон и портреты рекрутов.
- Боевой HUD по замерам окончательного DOM: четыре полосатые шкалы 2×2, оружие, круглый таймер, раздельные счётчики армий, квадратные кнопки, подпись приказа, группы с отдельными портретами/числами и деревянная миникарта. Геометрия проверяется на 1366×768, 960×650, 1920×1080, 800×600, 640×480 и 480×800: допуск 0,04 px, для ширины узкого счётчика 0,25 px из-за округления метрик шрифта.
- Меню боя по кнопке и Esc: бой останавливается, настройки применяются сразу, после закрытия сохраняется исходная тактическая пауза.
- Исходные формулы дыхания, шага, выпада, рубящего удара, укола, отдачи лука, галопа, шлейфа оружия и падения. Замах начинается при подготовке; попадание вызывает белую вспышку, не перезапуская замах.
- Контактная тень, пунктирные кольца врагов, заливка выбранных бойцов, щит блока, фракционные колышущиеся знамёна, флаги бегства, конная пыль и лучи попаданий. Варианты/фазы принадлежат отрисовке и не расходуют RNG симуляции.
- Двухколоночный обоз: кукла, восемь слотов, сетка с фильтрами, товары, подробности и двойной щелчок для надевания/снятия.
- Пять строк атрибутов и двадцать карточек перков с исходными описаниями и требованиями.

- Все шесть исходных цветов стяга: бойцы, составная экипировка, герб и свои поселения. Выбор сохраняется в метаданных героя, старые сохранения получают янтарный цвет. Пять дополнительных палитр хранят только изменённые RGBA-пиксели исходных атласов и заменяются по маске при подготовке; вражеские цвета сохраняются.
- Настройки быстрого боя: семь своих культур, восемь противников, размеры 50/100/200/1000. Армии создаются существующим правилом Generation, параметры передаются через координатор режимов.
- Создание героя и быстрый бой используют исходные CSS-рамки, шрифты, описания культур и адаптивные размеры. На 1366×768 ширина окон совпадает, высота отличается примерно на 2 px из-за округления строк.
- След рубящего удара героя: геометрия, фаза и прозрачность проверяются по 90 вызовам исходного battleDraw. Сглаживание и круглые окончания Godot могут давать растровые отличия.

## Осталось до полного 1:1

- Земля и растения используют зафиксированные визуальные образцы seed 4017. Seed продолжает задавать симуляцию и размещение растений, но **рисунок земли не воспроизводится для произвольного seed**. `TerrainView.use_original_ground = false` возвращает прежний шейдер.
- Штатные войска используют все четыре исходных варианта; составная кукла — внешность seed 7. Индивидуальные волосы, кожа, борода и лица спутников ещё требуют переноса. Фазы и варианты берутся из отдельного RNG Godot, их порядок не повторяет глобальный Math.random браузера.
- Выбор цвета собственного знамени и все настройки быстрого боя пока не перенесены.
- Основные кривые движения проверены по исходному Canvas. Расчленение, реплики, рельеф карты и постройки требуют дальнейшей сверки. Миникарта пока не показывает запечённые следы боя.
- Рынок, дипломатия, задания, спутники и специальные диалоги сохраняют работающие нативные действия, но не повторяют все исходные карточки и нижние блоки.
- Часть показателей показывает свойства предмета; итоговые характеристики героя нужно подключить через общее правило персонажа, без копирования формул боя в UI.

## Повторная выгрузка

Пользователю игры нужны только Godot и файлы проекта. Node и Chrome используются только при авторской выгрузке:

```text
npm install --no-save @napi-rs/canvas playwright
node godot/tools/export_visuals.cjs
node godot/tools/export_css_styles.cjs
godot --headless --path godot --import
godot --headless --path godot --script res://tools/build_theme.gd
```

Canvas-экспортёр читает исходные функции в изолированном контексте Node; CSS-экспортёр снимает финальный каскад `style.css` и `polish.css` в Chrome. В самой игре HTML и JS не исполняются. CSS нужно выгружать после Canvas, который оставляет резервные рамки.

## Проверка

```text
node build.mjs
node godot/tools/test.cjs <godot.exe>
godot --path godot --script res://tools/preview_capture.gd -- --out=<menu.png>
godot --path godot --script res://tools/world_shot.gd -- --seed=4017 --meet=ui_gear --out=<gear.png>
```

Новый `tests/integration/app/test_visual_interface.gd` проверяет реальные изменения инвентаря и рисунка при одиночном/двойном щелчке. Существующие тесты по-прежнему проверяют клики оружия, приказы, паузу и отступление. Архитектурная проверка запрещает визуальной библиотеке зависеть от игровых модулей.

### Сверка движения и размеров HUD

```text
node godot/tools/battle/export_motion.cjs
node godot/tools/battle/export_hud_layout.cjs
node godot/tools/battle/render_motion_reference.cjs <js-frames>
godot --path godot --fixed-fps 30 --script res://tools/battle/motion_preview.gd -- --out=<godot-frames>
npm install --no-save gifenc
node godot/tools/battle/compare_motion.cjs <js-frames> <godot-frames> <comparison-directory>
godot --path godot --script res://tools/battle_ui_capture.gd -- --out=<battle.png> --size=1366x768 --biome=grass
```

`export_motion` снимает 30 поз оружия, 160 матриц тела/оружия и 16 падений вызовами оригинальных функций Canvas. `test_unit_motion.gd` сравнивает матрицы с допуском 0,0001 и проверяет последовательность замах → попадание → отдача. `test_hud_layout.gd` проверяет реальные прямоугольники созданных Control по браузерным замерам.

В `tools/previews/animations-comparison.gif` сверху JS, снизу Godot: 60 кадров по восемь случаев при 30 fps. На RTX 3060/OpenGL в областях фигур 0,4961% пикселей отличаются больше чем на 16/255 хотя бы по одному цветовому каналу; средняя максимальная ошибка канала — 0,858/255. Подписи и фон исключены; метрика относится только к восьми образцам, не ко всей игре. Отчёт рядом в `animation-metric.json`.

Хеши симуляции до и после совпали: полевой бой `4137190000 / 2197583907`, осада `3076964788 / 4182612845` (1200 шагов). Информационный замер `view_bench.gd --n=300 --frames=120` до устранения лишней перекладки HUD: 601 живой боец, среднее 34,50 ms, медиана 32,25 ms, p95 48,97 ms на Windows/Godot 4.7.2/RTX 3060. Это не гарантия FPS на другом устройстве.

`test_banner_palettes.gd` сверяет пять палитр с исходными Canvas PNG, неизменность силуэта и вражеских цветов. `test_start_options.gd` нажимает реальные Control и проверяет параметры созданных армий; `test_save_v2.gd` проверяет сохранение цвета и миграцию старого формата. После изменения game_theme.gd обязательно пересобрать game_theme.tres через tools/build_theme.gd.
