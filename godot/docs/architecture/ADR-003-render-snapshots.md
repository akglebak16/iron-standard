# ADR-003: компактные снимки представления

Production view использует `BattleSimulation.render_snapshot()`. Динамические
колонки находятся в `RenderSnapshot`: позиции текущего/предыдущего тика,
флаги, стороны, группы, радиус, здоровье, направление, скорость и windup.
Старый словарный `snapshot()` временно остаётся для дифференциальных тестов,
инструментов и проверок паритета; он не вызывается в кадровом цикле view.

Каждый снимок владеет своими массивами до освобождения последним потребителем.
Симуляция не переиспользует выданный буфер. Колонки доступны через функции,
возвращающие явные `duplicate()`; изменение полученной колонки не меняет
снимок или симуляцию. Пространство имён `_render_` закреплено за классом снимка
и writer-сессией в манифесте. Анализатор запрещает доступ из других production
файлов, в том числе строковый get/set. Динамически конструируемые имена этот
статический анализ не доказывает; границы дополнительно проверяются поведением.
Статические определения внешности кэшируются и рекурсивно `make_read_only()`;
сам вызов `Dictionary.make_read_only()` не защищает вложенные контейнеры.
Источник: [Godot Dictionary](https://docs.godotengine.org/en/stable/classes/class_dictionary.html#class-dictionary-method-make-read-only).

Представление проверяет интерполированную позицию на видимость до создания
рисуночного словаря. Миникарта читает колонки напрямую. Для реплик создаются
только записи спутников; близость врага проверяется по колонкам. Обычный погибший
боец покидает поток снимков, его событие DOWN передаёт отделённое описание трупа.
Трупы сохраняются у представления и после падения запекаются прежним способом.

Это этап устранения аллокаций передачи данных, а не завершение SoA симуляции:
сама сессия ещё хранит объекты бойцов и архив погибших. Порог 1 мс для снимка
требует измерения; наличие PackedArray не доказывает достижение порога.
