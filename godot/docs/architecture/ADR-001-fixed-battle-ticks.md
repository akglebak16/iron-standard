# ADR-001: фиксированное время боя и владение переходами

Принято 2026-11-15 в рамках утверждённого blueprint.

`BattleSimulation.step()` выполняет 1/60 секунды. Внешний `FixedStepClock`
накапливает время, выполняет максимум четыре тика за вызов и предоставляет
долю интерполяции. Задолженность ограничена 0,25 секунды; отброшенное время
учитывается явно. Наличие потерь времени означает провал performance-приёмки.
Пауза не добавляет время. На скорости ×0,5 один тик требует двух кадров при 60 FPS.

Приказы, выбор оружия, ввод героя и отступление копируются в очередь команд.
События всех выполненных тиков сохраняются до передачи потребителю. Есть один
писатель состояния на главном потоке; worker будет возвращён только после
измерений оптимизированного ядра и определения владения буферами.

Снимки содержат предыдущие позиции для интерполяции. Это временное расширение
словарного формата, а не завершённый компактный BattleRenderSnapshot.
`advance(dt)` остаётся у старого backend для проверок паритета; представление
вызывает только фиксированный контракт. UI-тесты проходят через production scheduler.

`GameModeCoordinator` владеет корневой сценой режима. Меню и кампания запрашивают
переход сигналами, не загружают друг друга. Повторный запрос в одном кадре
объединяется; выход из кампании освобождает её подписки и циклические связи.
Переходы Campaign → Battle → Campaign пока остаются в прежнем адаптере мира.

Доказательства: `test_fixed_simulation.gd`, `test_battle_controls.gd`,
`test_scene.gd`, `test_mode_lifecycle.gd`, `test_world_dispose.gd`.
Цикл меню/карта устранён, список архитектурных исключений пуст.
