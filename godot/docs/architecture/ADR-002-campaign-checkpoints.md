# ADR-002: checkpoint кампании v2

Решение в рамках утверждённого этапа сохранений. Карта и каталоги восстанавливаются
из seed/определений; изменяемые поля перечислены явно в `WorldCheckpoint.FIELDS`.
Сохраняются игрок и его маршрут, поселения, партии, дипломатия, кризис, кланы,
задания, спутники, схватки, следующие ID, журнал и состояние отношений.
Часы включают паузу, скорость и оба дробных аккумулятора. RNG реестра партий
и рынка сохраняет seed и state; остальные системы используют эти же экземпляры.

Внешний файл остаётся JSON с `version`, `encoding`, `payload`, `sha256`.
Payload содержит Base64 от `var_to_bytes` только для отделённых значений.
`bytes_to_var_with_objects` запрещён. Схема допускает обычные контейнеры,
примитивы, StringName и Vector2, отвергает объекты и нечисловые/бесконечные координаты.
Типизированное бинарное представление сохраняет 64-битные RNG и дробные величины.
Это [штатный формат значений Godot](https://docs.godotengine.org/en/stable/tutorials/io/binary_serialization_api.html),
не дамп объектов движка. При смене encoding нужна новая миграция версии.

Обычный JSON v1 поддерживается прежним восстановлением с проверкой входа.
Новый вызов сохранения публикует v2. Отсутствующие в v1 RNG/аккумуляторы невозможно
восстановить задним числом: они получают детерминированные начальные значения.
Прогресс, армии, имущество и существующие идентификаторы v1 сохраняются.

Файловый адаптер пишет временный файл, закрывает и сверяет прочитанные байты,
затем публикует новое поколение переименованием в ещё не существующее имя.
Чтение выбирает последнее валидное поколение; незавершённые `.tmp` игнорируются.
Хранятся три поколения, исходный v1 не удаляется. Замена существующего файла через
`DirAccess.rename` не используется как гарантия атомарности Windows.
Тестовый профиль `user://` размещается в игнорируемой `.godot/` внутри workspace:
там файловые проверки имеют одинаковые разрешения записи и переименования.

Повреждённое поколение не заменяет рабочее состояние. Если пригодных сохранений
нет, экран загрузки возвращает игрока в меню и не создаёт новую игру молча.
Приёмка: точное равенство checkpoint до/после JSON-обёртки и продолжения мира,
миграция v1, восстановление предыдущего поколения после усечённой записи.
# Оставшиеся условия приёмки

Данные мира продолжаются точно, но этот коммит ещё не восстанавливает открытое
взаимодействие приложения (встречу, окно поселения, предложение добычи).
Перед завершением SAVE-V2 нужно перенести этот контекст в application кампании,
расширить проверку вложенных игровых записей и выделить persistence-порты.
Проверка round-trip не закрывает эти требования автоматически.
