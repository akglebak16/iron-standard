# ADR-022: Профиль ИИ стороны и отладочный снимок ИИ

Статус: принято для этапа «0-бой» плана ИИ ([DESIGN.md](../modules/ai/DESIGN.md), раздел 8).

## Причина

Новый ИИ боя сравнивается с нынешним на арене (DESIGN.md 7.1), а его решения
нужно видеть в бою (4.8). Для этого нужны два контракта, которых раньше не было:
какой ИИ ведёт сторону и как узнать, что и почему он решил, не трогая состояние боя.

## Решение

**Профиль ИИ в BattleSetup.** Поля `player_ai_profile` и `enemy_ai_profile`
(строки, есть и в ресурсе сценария). `Config.AI_PROFILE_REFERENCE` — нынешний
таймерный ИИ `rules/tactics.gd`, замороженный эталон арены; он по умолчанию у врага.
`Config.AI_PROFILE_PLAYER` (пустая строка) — сторона по приказам игрока, по умолчанию
у игрока. Профиль выбирает «мозг» в `core/battle/simulation/ai/profiles.gd`: скрипт
с двумя статическими функциями контракта `tactics.gd` — `enemy_step(battle, side,
elapsed, dt)` и `siege_step(battle, elapsed, dt)`. Новый ИИ добавляется туда же под
новым именем. Фабрика отклоняет неизвестный профиль и осаду, где у защитников нет ИИ
(их мозг ещё и выбивает и открывает ворота). Профили по умолчанию дают прежний бой
побитово: тот же порядок вызовов, тот же RNG. Мозг стороны игрока, если он задан,
вызывается после мозга врага; в игре его нет.

**Запись решений и отладочный снимок.** `simulation/ai/decision_trace.gd` хранит
последнее решение каждой группы, план стороны и последние записи кодами
(`DECISION_*`, `REASON_*`, `PLAN_*` в `tactics.gd`), без текстов для игрока.
Сессия держит запись в `State.ai_trace` только пока включена отладка
(`BattleSimulation.set_ai_debug`); иначе там `null`, и мозг пропускает запись.
Ни одно правило запись не читает, в `snapshot()`, `RenderSnapshot` и результат она
не входит. `BattleSimulation.ai_debug_snapshot()` собирает отделённый словарь
(`application/ai_debug_snapshot.gd`): профиль и план сторон, приказ, центр,
направление, точку обхода и последнее решение групп, оценку поля (DESIGN.md 4.1)
и режим каждого бойца. Worker перед чтением дожидается пакета, как прочие getters
(ADR-021). Оверлей `apps/godot/presentation/battle/hud/ai_debug_overlay.gd`
по F3 переводит коды на русский и рисует снимок.

**Оценка поля и расписание** (`field_assessment.gd`, `decision_schedule.gd`) —
внутренние части battle. Оценка считается по запросу одним проходом по колонкам;
в бою её пересчитывает только отладка на тиках командира по расписанию. Решения
`tactics.gd` к расписанию не подключены: они сдвигают центр групп каждый тик и
считают таймеры по `dt` (в старых дифференциальных тестах `dt` произвольный), так
что их перевод на редкие тики меняет бой. Расписание — отдельный объект с тремя
запросами (`commander_due`, `squad_due`, `due_squads`); его может заменить
реализация требования `BATTLE-AI-NAVIGATION`.

## Проверки

- `tests/integration/test_ai_debug_snapshot.gd`: бой на поле и в осаде с записью
  с начала, с переключением записи и с изменением выданных снимков совпадает с боем
  без записи по снимкам, событиям и результату; worker отдаёт тот же снимок, что и
  синхронная симуляция; неизвестный профиль и осада без ИИ защитников отклоняются;
  профиль действительно выбирает мозг; коды причин для отмены погони и атаки вплотную.
- `tests/unit/battle/ai/test_field_assessment.gd`, `test_decision_schedule.gd`.
- `tests/unit/battle/presentation/test_ai_debug_overlay.gd`: F3 включает и выключает
  запись, у каждого кода `tactics.gd` есть русская подпись.
- `tests/integration/test_ai_arena_smoke.gd`: арена задаёт профили обеих сторон
  через BattleSetup, бой повторяется по seed, замер фазы ИИ бой не меняет.
- Прежние `test_native_movement.gd`, `test_spatial_full_battle.gd` и остальные тесты
  проходят без правки эталонов.
