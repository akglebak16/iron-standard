# ADR-018: исходная графика main в архитектуре миграции

Дата: 2026-11-15. Основание: rebase ветки миграции на `8a97999`
(PR #77 и #79). До rebase сохранена локальная ветка
`codex/backup-blueprint-before-main-rebase-343b4bc`.

## Решение

- Общие атласы, шрифты, тема и визуальные функции находятся в
  `apps/godot/visuals/`. У них три потребителя: меню, бой и кампания.
  Содержимое изображений, шрифтов и лицензий сохраняется без перегенерации.
- Визуальная библиотека не получает игровые каталоги или RNG симуляции.
  Существующий тест границ сохраняется; правила core/runtime не ослабляются.
- Выбор ресурса по имени проходит через сгенерированный `asset_paths.gd`:
  все ссылки видны анализатору, свежесть списка обязательна в architecture gate.
- Тема проекта на диске не зависит от импортированного кэша. Autoload
  `theme_bootstrap.gd` устанавливает полную тему перед игровыми сценами и
  скриптовыми тестами. Он не содержит игрового состояния. Это позволяет
  первому импорту на чистом checkout завершаться без ошибок загрузки шрифтов.
- Меню запрашивает быстрый бой/осаду сигналом, а координатор создаёт контекст.
  Возврат из боя также проходит через координатор. Прямые переходы из
  main.gd в main_menu.tscn создали бы цикл ресурсов и обошли lifecycle.
- Новое представление получает компактные снимки миграции. Изображения
  разрешаются после culling, павшие бойцы берутся из отделённых событий.
  Смерть и уплотнение активного хранилища не пересобирают портреты всего войска;
  новые идентификаторы запрашиваются при старте и приходе подкрепления.
- Меню паузы использует текущий фиксированный scheduler; ожидания удалённого
  worker не возвращаются. Камера кампании/боя и кэш статической карты сохранены.

## Проверки

`tools/architecture.cjs`, отрицательные fixtures, `test_boundaries.gd`,
`test_mode_lifecycle.gd` (включая быстрый бой, осаду, паузу, двойной запрос и
освобождение сессии), `test_battle_controls.gd`, `test_hud_layout.gd`,
`test_unit_motion.gd`, `test_visual_interface.gd`, чистый импорт, release-smoke.
Fingerprints двух боёв по 1200 тиков должны совпадать с веткой до rebase.
Ограничения визуального паритета остаются в `docs/modules/VISUAL_PARITY.md`.
