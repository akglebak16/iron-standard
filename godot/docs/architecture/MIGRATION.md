Утверждено владельцем 2026-11-15. Ветка: `codex/godot-blueprint-migration`.
Исходная ревизия: `096df30ad9e279d89aacff7dc4e8720903e8a700`.
Полный исходный документ — `BLUEPRINT.md`. Этот файл фиксирует исполнение,

После отделения файлового доступа и editor Resource выполнен механический
перенос 336 оставшихся файлов в целевые корни. Реестр исходных/текущих путей —

незавершённое SoA, Campaign API, схемы контента и performance. Handles с
поколениями и активное уплотнение уже реализованы; координаты и скорости
стали авторитетными packed-колонками (ADR-015).

Перенос графики main `8a97999` после rebase описан в ADR-018; результаты
проверок — [отчёт интеграции](../benchmarks/main-rebase-2026-11-15.md).
Это не меняет незакрытые требования миграции.

Оптимизация боя после rebase ведётся отдельно в `codex/battle-2000-performance`.
Добавлены горячие SoA-колонки, последовательный пакет AI/движения, локальные
запросы снарядов и осадной плотности, атлас и пакетное представление, worker
с явной публикацией снимков. Контракты — ADR-019/020/021; результаты выбранных
сценариев — [отчёт 1000×1000](../benchmarks/battle-2000-2026-11-16.md).
Успешный benchmark одного состава не закрывает полную матрицу ниже.

Машиночитаемая трассировка требований и проверок: `requirements.json`.
`node godot/tools/architecture.cjs --acceptance` требует завершения всех требований;
обычная проверка запрещает новые нарушения, но не означает завершение миграции.

## Принятые решения

- Корень движка остаётся `godot/`; целевые области: `apps/godot`, `core`,
  `runtime`, `adapters`, `content`, `tests`, `docs`, `tools`.
- Обязательная платформа Windows x64. Godot 4.7.2 закреплён.
- Эталон: i5-14400F, RTX 4070 SUPER, 1920×1080, Compatibility.
- Цель: 1000 обычных активных юнитов с весом 1 на сторону; герой/спутники
  считаются отдельно. Лимит в игре 300/500/1000, по умолчанию 1000.
- Сохраняются механики, контент, стиль, баланс и сохранения. Побитовый
  паритет требуется для перемещения кода, но не для согласованных новых алгоритмов.
- C++ только после устранения алгоритмических затрат и замера p95 тика >6 мс.
- Не реализуем новые Settlement/Dynasty/Politics системы; существующие
  войны, кланы, вассалы и экономика обязательно сохраняются.

## Приёмка

Release: frame p95 ≤16.67 мс, p99 ≤25 мс; simulation p95 ≤6 мс;
snapshot p95 ≤1 мс. Скорость игрового времени ×1 без отставания.
Сценарии 100/500/1000 на сторону: сближение, контакт, кавалерия, залп,
проходы осады, построения, бегство, подкрепления. Камера близко и общий план.
Прогрев, 60 секунд измерений, пять повторов, фиксированные seeds.
Записываются реальные численности, память, CPU/GPU, кадры, фазы, события,
пространственные запросы, collision candidates, draw calls, Nodes и voices.
Изоляционные прогоны не подменяют полную игровую нагрузку.

Результаты профиля должны включать SHA и состояние рабочего дерева.
Нельзя объявлять скорость release по debug/headless или старой ревизии.
Регрессия p95 >10% требует разбора; неизвестные измерения не считаются нулём.
