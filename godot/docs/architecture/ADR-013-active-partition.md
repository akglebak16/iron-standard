# ADR-013: активный массив и история результата

Горячие правила боя перебирают `State.active_units`. В конце тика погибшие и
ушедшие удаляются из него стабильным уплотнением: относительный порядок
живых, разрешение равных расстояний и порядок боевых действий сохраняются.
Поколения handles уже освобождены при смерти/выходе; relocation обновляет
их плотные индексы. SpatialIndex перестраивает индексы с сохранением пулов
бакетов. Состав групп также освобождается от неактивных записей.

`State.units` пока является внутренней append-only историей Unit для результата
и прежнего диагностического snapshot. Result обходит её в исходном порядке,
чтобы RNG определения раненых не изменился. История не передаётся представлению.
Production snapshot считает сводку по активным, а визуальные данные получает
из списка активных и именованных погибших; обычные трупы принадлежат DOWN event.
Для интерполяции используется history_index, который не меняется при уплотнении.
После первого снимка погибшего previous_position становится его последней
позицией, как при прежнем полном обходе. Прежние fingerprints сохранены.

UnitId выдаётся отдельным монотонным счётчиком, не длиной активного массива.
Тест удаляет 98 из 100 записей, проверяет перемещение handles/spatial queries,
уникальный ID подкрепления, состав групп, точный результат и состояние RNG.

Переход ещё не завершён: записи остаются объектными, history хранит полные Unit,
а previous_positions резервирует место по истории. Авторитетные SoA и компактные
данные архива результата остаются в BATTLE-SOA-HANDLES со статусом pending.
Этот этап убирает историю из горячих обходов, но не объявляет все затраты памяти
устранёнными. Профиль отдельно записывает storage_compaction и размеры массивов.

Проверены 90 файлов тестов, release-smoke, прежние fingerprints поля/осады.
Короткий CPU release contact 1000×1000 на P-ядрах: p95 тика 24.450/23.537 мс,
снимка 5.134/4.699 мс (60 тиков прогрева + 180 измерения, два повтора).
Полный отчёт: `../benchmarks/active-compaction-pcore.json`.
Это близко к предыдущим handles-запускам 24.573–24.948 мс; целевые пороги
по-прежнему не выполнены, диагностическое сравнение не заменяет приёмку.
