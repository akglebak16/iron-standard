# Роудмап разработки

Все задачи по игре — в папке `roadmap/tasks/`, **одна задача = один файл**. Из них собирается доска:
**https://akglebak16.github.io/iron-standard/roadmap/** (колонки по статусам, фильтры, поиск, карточка по клику).
Доска пересобирается при каждом пуше в любую ветку, где меняли `roadmap/tasks/`, и показывает свежий статус из всех веток (метка ⎇ на карточке — из какой).

## Править прямо на доске (для людей)
Профиль справа сверху → выбрать себя и вставить личный токен GitHub (fine-grained, только репозиторий `iron-standard`, право **Contents: Read and write**; хранится в браузере). Дальше: перетаскивать карточки между колонками (на телефоне ‹ ›), клик по кружку на карточке — сменить исполнителя, «Взять» — взять себе, клик по карточке → «✎ Изменить» — всё остальное, «＋ Новая задача». Всё пишется в ветку `roadmap-board` (не в `main`), оттуда Pull Request в `main` открывается сам, сливает Глеб.
ИИ так не делают: ИИ правит файл задачи в своей ветке, как описано ниже.

## Люди
Список исполнителей — `roadmap/people.json` (имя и цвет): Глеб, Виталий, Захар, Викентий. Новый человек = новая строка там, иначе `owner` в задаче не пройдёт проверку.

## Главное правило
**Ни одна работа не идёт мимо роудмапа.** Берёшь задачу из списка — отметь её. Делаешь что-то, чего в списке нет (баг, мелочь, идея по ходу), — заведи пункт с `outside: да`, даже если уже всё сделал. Так все видят, что сделано, что в работе и кто чем занят.

## Файл задачи
Имя — латиница, цифры, дефисы, по смыслу: `roadmap/tasks/undead-waves.md`. Имя файла = id задачи; ветку лучше называть так же.

```markdown
---
title: Волны нежити в бою
status: можно брать
owner:
area: бой
priority: обычный
created: 2026-11-14
pr:
done:
outside: нет
---
Что сделать и зачем. Что значит «готово». Можно списки и чекбоксы:
- [x] сделанный шаг
- [ ] оставшийся шаг
```

- `status` — одно из: `идея` (не решено, делать ли) · `можно брать` (решено, свободно) · `в работе` · `на проверке` (PR открыт) · `готово`.
- `owner` — кто делает: `Глеб`, `Виталий` или имя третьего. Обязателен для `в работе`. ИИ пишет имя своего человека, не своё.
- `area` — область: `бой`, `мир и карта`, `фракции и баланс`, `спутники`, `герой и снаряжение`, `интерфейс`, `графика`, `звук`, `мультиплеер`, `порт`, `релиз`, `процесс`. Новая область — можно, но сперва глянь, нет ли подходящей.
- `priority` — `высокий` / `обычный` / `низкий`.
- `created`, `done` — даты `ГГГГ-ММ-ДД`. `pr` — номер Pull Request.
- `outside: да` — пункт заведён по ходу работы, вне плана.

## Жизненный цикл
1. **Перед началом работы** открой доску или `roadmap/tasks/` и найди свою задачу.
   - Есть и свободна → в своей ветке поставь `status: в работе`, `owner`, закоммить и **сразу запушь ветку** — так задача станет занятой для всех.
   - Уже `в работе` у другого → не бери, договорись с ним.
   - Нет в списке → заведи файл (`outside: да`, если это не из обсуждённого плана), сразу `в работе`.
2. **Открыл PR** → `status: на проверке`, `pr: <номер>`.
3. **Перед слиянием** (последним коммитом в ветке) → `status: готово`, `done: <дата>`, чекбоксы закрыты. После слияния в `main` задача готова на доске.
4. Бросил задачу → верни `можно брать`, очисти `owner`, допиши в описании, где остановился.
5. Большая задача → разбей на несколько файлов (`graphics-icons`, `graphics-battle`…), в описании родителя перечисли их.

## Правила
- Чужие задачи не удаляем и не переименовываем. Неактуальное — `идея` + пометка в описании, удаляет только Глеб.
- Задачи по мультиплееру (`area: мультиплеер`) берёт только Глеб.
- Новую идею, которая меняет концепцию игры, заводи как `идея` и спроси Глеба — не начинай делать.
- `status: готово` ставь только когда работа реально слита или вот-вот сливается этим PR.
- Править статус можно и без ИИ: кнопка «✎ Изменить на GitHub» в карточке открывает файл в редакторе GitHub, он сам предложит ветку и PR. Кнопка «＋ Новая задача» открывает шаблон.

## Проверка
`node roadmap/build.mjs --check` — проверяет все файлы (статус, owner для «в работе», даты, имена). Её же гоняет CI: криво оформленная задача = красный PR.
`node roadmap/build.mjs` — собирает `roadmap/index.html` (в git не идёт), открой в браузере.
`node roadmap/build.mjs --branches out.html` — как на сайте: main + свежие статусы из всех `origin/*` (сначала `git fetch`).
