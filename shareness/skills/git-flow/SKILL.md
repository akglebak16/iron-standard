---
name: git-flow
description: Ветки, коммиты, Pull Request и слияние в main. Применять при каждом пуше и PR.
---
1. Перед работой над кодом найди issue задачи; если её нет — создай (`gh issue create` или через API) и только потом начинай.
2. Одна задача (issue) — одна ветка и один PR с `Closes #N`. Несколько задач в одном PR не собираем.
3. Работай в своей ветке, не в `main`. Имя по смыслу (`godot-world-time`, `companion-vikenty`). В `main` напрямую не пушит никто; свою ветку пушь сколько угодно (`git push -u origin <ветка>`), ИИ может делать это сам, не спрашивая.
4. Перед пушем — проверки из навыка `build-and-test` (архитектура и затронутые тесты) и раздел «## Для игрока» в описании PR (навык `changelog`).
5. Коммит: короткое русское описание, что изменилось.
6. В `main` — только через Pull Request из ветки (`gh pr create --base main`). Сливает Глеб после зелёного CI («Godot — архитектура и Windows»). Если `main` ушёл вперёд и появился конфликт, перенеси ветку на свежий `main` (`git rebase origin/main`), реши конфликт и запушь ветку заново.
7. Не сливай в `main` то, что ломает игру, сохранения или тесты, и то, что меняет игру целиком (другая эпоха, жанр, огнестрел вместо средневековья), без явного «да» Глеба (см. «Жёсткие правила» в `CLAUDE.md`).
