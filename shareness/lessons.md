## Процесс и CI
- 2026-11-17 — Исправления журнала #124 остались только в локальной ветке, поэтому запуск свежего main снова показал старый UI. Перед запуском main проверяй, вошли ли недавние локальные исправления в него; отсутствие исходного SHA ещё не потеря кода — сверяй squash/rebase по патчам и действующему коду. Готовую задачу доводи до PR с Closes #N, а в ответе явно различай локальную ветку, опубликованный PR и слитый main.
- 2026-11-16 — Задачи не висят: работа над кодом начинается с issue (найти открытую или создать), PR закрывает её строкой `Closes #N` при слиянии в `main`. Workflow `pr-issue.yml` краснеет, если строки нет. Ссылка без ключевого слова («#N», «по issue») issue не закрывает.
- 2026-11-16 — Releases выпускают Godot-игру сами: `release.yml` запускается на каждый push в `main`, по API `commits/{sha}/pulls` находит слитый PR и выпускает версию, только если его «Для игрока» не пуст. Сборка на Windows с полным набором тестов и release-smoke идёт около 10 минут; кеши импорта и native только читаются. Решение Глеба: каждый PR с изменениями для игрока — новая версия.
- 2026-11-16 — JS-версия удалена (`src/`, `server/`, браузерные тесты, сборка `index.html`, GitHub Pages, экспортёры из JS). Источник истины — Godot-проект: каталоги в `godot/content/gameplay/` правим напрямую, графику — как файлы. CI — один workflow «Godot — архитектура и Windows»: в PR тесты выбираются по графу ссылок `res://` от изменённых файлов, полный набор ночью и по кнопке, после слияния в `main` только прогрев кешей. Зависимость, собранная в коде из кусков пути, граф не увидит: ссылайся на ресурс строкой `res://...`.
- 2026-11-14 — `CHANGELOG.md` убран, история версий — в GitHub Releases (v0.2.0…v0.18.0 перенесены workflow `import-changelog.yml`). Изменения для игрока пиши в PR в разделе «## Для игрока»; релиз собирает workflow «Выпустить версию». Из облачной сессии Claude создавать релизы через API нельзя (прокси запрещает) — только через Actions.
- 2026-11-14 — релиз сам не появляется: его выпускает вручную workflow «Выпустить версию» (Actions → Run workflow), заметки берутся из «## Для игрока» PR, слитых после прошлого релиза. Разделитель `---` перед подписью Claude Code раньше попадал в текст и ломал проверку на «нет» (в релизе висели «нет» и «--- (#N)»): `release-notes.mjs` теперь его отбрасывает. Из облачной сессии релизы можно создавать запуском workflow, но править уже созданные нельзя.
- 2026-11-14 — если в workflow ломается YAML, у workflow пропадают все триггеры (даже `workflow_dispatch`, запуск даёт 422): после правки workflow проверять `python3 -c "import yaml; yaml.safe_load(open('<файл workflow>'))"`.
- 2026-11-15 — Godot для тестов качается с github.com/godotengine/godot/releases (zip 4.7.2-stable); тесты быстрее гонять параллельно: `find godot -name 'test_*.gd' | xargs -P 8 ...`, а `godot/tools/test.cjs` идёт последовательно и на всём наборе занимает много минут.
- 2026-11-16 — Godot-тесты в CI шли 8,5 минут: 104 теста по одному плюс импорт всех картинок с нуля (до 2 минут, однажды упёрлось в таймаут). Теперь тесты идут в 4 потока с отдельной папкой данных на каждый, импорт кешируется (`actions/cache`, ключ — хеш картинок), правки node-скриптов в `tools/` не запускают полный набор. Новый тест не должен зависеть от порядка запуска и писать в общие файлы вне `user://`.
- 2026-11-16 — Время проверки разделяй на native-сборку, импорт и тесты. История длительности нужна только для запуска долгих тестов первыми, а не для кеширования успешных результатов. Локальный --changed должен видеть staged/unstaged/untracked; C++/hpp требуют полного набора, потому что res:// граф их не видит. Кеш CI не отменяет проверку SHA закреплённых инструментов и fingerprints объектов.
- 2026-11-16 — Кеш импорта Godot в CI не работал ни разу: Windows-раннер выкачивает текстовые файлы с CRLF, а Godot, увидев `.import` не с LF, заново импортирует все 446 ассетов (~2 мин), даже если `.godot/imported` восстановлен целиком. Лечится `.gitattributes`: `*.import text eol=lf`. Второе: в PR GitHub отдаёт кеши только своей ветки и main, поэтому кеш импорта и native прогревается на main отдельным запуском после слияния (без тестов), а сохраняется сразу после подготовки, до тестов, чтобы упавший тест его не терял. Лимит времени теста — страховка от зависания: 4 процесса на 4 vCPU раннера замедляют тяжёлый тест в 2–4 раза, поэтому лимиты с запасом втрое от худшего замера (по умолчанию 90 с).
- 2026-11-16 — В bash не передавай в `node -e` строку с бэктиками внутри двойных кавычек: оболочка выполнит их как команды (`` `world_wars.gd` `` запустится как скрипт). Правки с Markdown и кодом передавай файлом (JSON с парами замен) или инструментом правки.
